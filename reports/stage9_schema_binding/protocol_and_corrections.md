# Stage 9 预注册协议与修复记录

日期：2026-10-16（北京时间）。本阶段只推理，未新增训练、商业 API 或付费实例。

## 无效试运行 v1

旧脚本在 JSONL 写入时启用了 `sort_keys=True`。这会消除 properties 的反转，并使 A/B 的语义字段顺序也不一致。旧 Base pilot 24 条和正式试运行 96 条不能用于因子结论，原始数据、脚本快照、预测与日志全部保留。修复不是针对准确率进行调参。

另外，旧构造的聚合方式与汇率穿越方向缺少明确的枚举取值约定，且 pilot 包含在旧正式数据中。v2 补齐枚举解释，将 pilot 与正式请求分开。v2 的 24 个请求使用预先固定的新地点、数值、编号与时间组合，未查看其模型结果后修改 Gold。

## 固定设计

- 6 个人工受控工具模板，每个模板 4 个正式请求，共 24 个任务、96 个四条件实例。Pilot 为另外 6 个请求，模板与正式集共享，因此不是未见工具家族泛化测试。
- A 为语义名称原顺序，B 为不透明名称原顺序，C 为语义名称反转顺序，D 为不透明名称反转顺序。字段与 required 列表同时反转；只研究序列化顺序整体，不区分 properties 与 required 两个位置来源。
- 单工具、四字段、其中一个 optional；12 个任务显式要求 optional。未提及 optional 时应省略，无默认值。中文请求、英文参数描述。
- 复用 Qwen2.5-1.5B-Instruct、FDSRC、FCTW；贪心解码、160 新 token、相同原生模板；GPU 0 单进程，显存分配上限 16%，每次运行前至少需 8GB 空闲。
- 主要效应为 B-A、C-A、D-C-B+A。按基础任务做 5000 次配对 Bootstrap。24 个请求来自 6 个模板，额外报告模板聚类敏感性，不能宣称 24 个完全独立工具家族。
- 评分先还原规范参数名，再校验类型和语义值。布尔值不能被 0/1 代替。额外字段导致 Arg Exact 失败；解析错误与调用数量错误需区别说明。

## 免训练基线的固定规则

两种基线应用于正式 B/D 条件，每个模型各 48 条，规则在 v2 正式推理前固定，不查看 Gold 值或模型失败来选名字。

1. 显式映射：提供实际 ID、原语义参数名、已有描述的对应表，仍输出真实 ID。这增加名称语义信息，是诊断条件，不是同信息量的公平算法对照。
2. PA-Tool-inspired 简化命名：只读取英文字段描述，分词为英文字母词，删除固定集合 `optional,the,of,a,an,in,for,flag,number`，取前三个词拼接下划线；冲突按出现顺序加整数后缀；输出映射回真实 ID。工具名不变，不使用 Gold 或原语义参数名生成别名。

已核查 [PA-Tool 原论文](https://arxiv.org/html/2510.07248v3) 与[官方仓库](https://github.com/holi-lab/PA-Tool)。原方法由目标模型采样候选名称、计算编辑距离聚集程度，再选择名称；所访问的官方仓库提供展示页。这里省略模型候选采样与 peakedness 选择，因此不能将本地基线的成功或失败归因于 PA-Tool 原方法。

## 条件实验与停止规则

只有在直接调用中发现参数相关配对退化，才选择失败与成功控制开展字段识别。字段识别必须以明确用户条件作为目标，不能只给一个可能重复的数值。它是行为诊断，不证明内部理解或遗忘机制。

若独立请求上不复现主要退化，完成已冻结的免训练对照后结束，不扩大数据或搜索提示以制造差异。

## 执行后的评分审计

复用已有 Parser 的无调用语义，将 FCTW 的明确拒绝与破损 JSON 区分；端到端参数分数之外，增加正确调用条件下的 Binding 与遗漏率。修改仅涉及离线归因，不改变预测或冻结 Gold。中间评分快照保留，最终分类见 results/final。

发现商品类别自由字符串存在中英同义表示歧义后，不增加模型输出驱动的同义词接受规则，而是保存原严格分数，并对三模型四条件统一排除整个商品模板作事后敏感性分析。该分析不属于新增独立确认实验。

FCTW 加载错误为未恢复 Git LFS 权重。GitHub 下载可达但速度较慢，停止了本次下载，改从已有本机备份恢复到独立目录，文件 SHA-256 与原指针一致。失败日志、原始指针和历史检查点均保留。

字段识别集按模型错误并集选出六个任务，控制来自跨模型成功集合；因此不是每个模型的全部控制都正确。该选样局限以及字段识别使用不同提示协议的限制均写入最终报告。没有根据探针结果修改字段名或提示。
