# CCPD-v1.1：动态工具合同的 Knowing–Acting 机制验证报告

日期：2026-10-17  
基础模型：`Qwen2.5-1.5B-Instruct`  
当前判断：**REVISE（F4 结果出来前的阶段判断）**

## 1. 研究问题与前期证据

CCPD-v1 希望利用同一请求下的可满足合同与不可满足合同配对，消除请求层面的共同调用倾向并强化合同敏感性。E0 已否定其核心理论主张：配对乘积目标没有独特的去偏置驻点，采样联合奖励还会制造严重的全零奖励组。E1 随后发现，四个历史模型在 21 对严格样本上的受控 Paired Concordance 均为 100%，但原生 Pair Success 仅为 0%–9.52%。E2 证明严格合同 Gold 可以构造，但原联合奖励预检没有产生有效优势。

因此本轮不修补 CCPD-v1 的配对 GRPO，而检验三个竞争解释：

1. 原生提示没有明确允许拒绝，或 Parser 不认识拒绝格式；
2. 原生生成位置缺少合同可满足性信息；
3. 表征中存在信息，但启用工具后的生成策略没有稳定利用它。

## 2. F0：数据构造与 Gold 可靠性

### 2.1 数据来源与冻结版本

数据来自 BFCL 官方数据的固定提交 `6ea57973c7a6097fd7c5915698c54c17c5b1b6c8`。生成器扫描 1000 条候选：接受 466 条；400 条因不是单调用被排除；130 条没有严格目标字段；4 条未通过执行检查。最终冻结 `frozen_v2` 共 203 对，数据 SHA-256 为：

`1ff1e8ab5746eecc42510aeac083c12c4c0367e710e419e11f6404cee40b60bf`

| 划分 | 配对数 | 历史未暴露 | 说明 |
|---|---:|---:|---|
| Train | 160 | 4 | 用于 Probe 与 F4 SFT |
| Dev | 4 | 4 | 只用于冻结阈值和协议检查 |
| Test-ID | 10 | 10 | 新请求，约束类型在训练内 |
| Test-OOD-Family | 25 | 25 | 工具家族与训练集完全隔离 |
| Test-OOD-Constraint | 4 | 4 | 训练未见的 `const` 约束 |

约束分布为 enum 103、numeric minimum 51、numeric maximum 45、const 4，共涉及 203 个基础任务。所有划分均以基础任务为单位，`source_id` 和归一化请求模板不跨划分；OOD-Family 的工具家族与训练集隔离。

### 2.2 可执行语义

每个配对满足：请求不变、单工具闭世界、工具名与属性顺序不变、目标字段必填且无默认值、请求中存在目标值的直接证据。E+ 的唯一 Gold 调用通过合同，E- 明确排除同一目标值。这里的执行器验证 JSON Schema 子集，不代表真实外部 API 的全部业务语义。

### 2.3 捷径与人工审核

第一版数据被主动废弃：字符串负例的 `unsupported_*` 前缀泄漏了标签。v2 将 enum 两侧基数固定为 1，并让替代字符串与 Gold 等长、保持空格和标点形态。仅使用长度、Token 数、字段数、约束键、基数和约束标量的浅层逻辑回归，在四个非训练划分上的 Balanced Accuracy 均为 50%，AUROC 为 50.00%–50.48%。

固定种子分层人工检查 30 对，包括全部 Dev、Test-ID、OOD-Constraint，以及 8 个 OOD-Family 和 4 个 Train 样本，结果为 30/30 通过。该抽查支持把数据用于机制 Pilot，但不能证明全部 203 对具有某个预设错误率上界。

## 3. F1：简单提示能否解决原生调用失败

在 43 个 Dev/Test 配对、固定贪心解码下，对 Base 比较四种提示：原生提示、明确允许拒绝、固定拒绝格式、合同优先决策指令。共保存 344 条原始生成。

| 条件 | Native Pair Success | Valid Call | Invalid Call / False Call | Valid 完整调用 |
|---|---:|---:|---:|---:|
| A 原生 | 0.00% | 100.00% | 100.00% | 46.51% |
| B 允许拒绝 | 0.00% | 100.00% | 100.00% | 48.84% |
| C 固定拒绝格式 | 0.00% | 100.00% | 100.00% | 46.51% |
| D 合同优先 | 0.00% | 100.00% | 100.00% | 48.84% |

四种提示均没有产生一次拒绝，Parser Failure 为 0。该结果排除了“仅仅没有拒绝许可”以及“模型拒绝了但 Parser 没认出来”两种解释。提示差异只造成可满足侧参数生成的轻微波动。

## 4. F2：原生生成位置是否包含合同信息

### 4.1 协议

输入使用与 F1-A 完全相同的原生 Chat Template。在 Assistant 开始生成前，提取最后一个上下文 Token 的 embedding、中层、后层和最后层隐藏状态。仅在 160 个训练配对上拟合标准化线性 Logistic Probe；层集合和阈值预先固定，不使用测试集选层。另设两组控制：不读取请求语义的表面统计，以及字符 TF-IDF。

### 4.2 核心结果

| 表征 | Test-ID AUROC / BA | OOD-Family AUROC / BA | OOD-Constraint AUROC / BA | OOD-Family Pair Concordance |
|---|---:|---:|---:|---:|
| 表面统计 | 0.500 / 0.500 | 0.502 / 0.500 | 0.438 / 0.500 | 32.00% |
| 字符 TF-IDF | 0.740 / 0.650 | 0.685 / 0.600 | 0.563 / 0.625 | 88.00% |
| 中层 | 0.880 / 0.750 | 0.776 / 0.700 | 0.875 / 0.750 | 100.00% |
| **预注册后层** | **0.930 / 0.800** | **0.890 / 0.840** | **0.875 / 0.750** | **100.00%** |
| 最后层 | 0.850 / 0.800 | 0.810 / 0.760 | 0.875 / 0.750 | 100.00% |

后层在 OOD-Family 上的平均 E+/E- 概率差为 0.601，配对 Bootstrap 95% CI 为 `[0.465, 0.733]`。但固定 0.5 阈值下的 OOD-Family Pair Decision Success 只有 68%，ECE 为 0.143，说明相对排序强于绝对校准。

### 4.3 能够与不能够推出的结论

结果支持：在原生生成起点，后层表征包含可由少量监督线性读出的合同匹配信号，并能迁移到未见工具家族。它不支持“模型内部已经存在独立且正确的合同判断模块”。字符 TF-IDF 也有 88% 的配对排序，说明数据本身包含可学习的语义匹配规律；后层的优势主要体现在更高的绝对 AUROC、Balanced Accuracy 和更大的分数间隔，而不是只有模型表征才能完成配对排序。

## 5. F3：合同判断能否转化为正确行动

### 5.1 原生接入结果

在同一 43 对上比较：工具注册状态下自主输出判断、Oracle Gold、冻结后层 Probe、刻意反转标签。判断以固定文本写入系统上下文，然后继续原生工具调用。

| 条件 | 判断准确率 | 判断 Pair Success | Native Pair Success | False Call | Valid 完整调用 |
|---|---:|---:|---:|---:|---:|
| 工具注册下自主判断 | 0.00% | 0.00% | 0.00% | 100.00% | 48.84% |
| **Oracle** | **100.00%** | **100.00%** | **0.00%** | **100.00%** | 46.51% |
| **后层 Probe** | **83.72%** | **67.44%** | **0.00%** | **100.00%** | 46.51% |
| 反转标签 | 0.00% | 0.00% | 0.00% | 100.00% | 44.19% |

Oracle、Probe 和反转标签对调用/拒绝行为完全没有因果影响：模型对两侧都调用。Oracle 条件下“判断正确时行动正确率”为 50%，恰好来自所有 E+ 被调用、所有 E- 也被调用。

工具注册状态下的自主判断没有输出二元标签，而是在 16 Token 上限内直接开始工具调用。这揭示了一个具体协议偏置：函数工具一旦通过原生模板注册，Base 的首个生成动作强烈偏向 `<tool_call>`。

### 5.2 普通文本两阶段强基线

为隔离上述格式偏置，补充了不注册工具、但把相同 Schema 完整序列化为普通文本的判断阶段；第二阶段再恢复原生工具调用。该判断仅有 51.16% 准确率、2.33% Pair Success，随后行动仍为 100% 调用。它没有复现 E1 的 100% Concordance，因为 E1 测量的是受控选项的相对分数，而这里要求模型自回归地产生离散判断。

### 5.3 解释边界

F3 排除了“给模型一句正确判断就能桥接行动”的简单解释，也说明错误不只是判断器精度不足：Oracle 都不能改变调用行为。当前最符合证据的解释是，工具模板触发的原生生成策略对显式判断不敏感；但这仍可能是 Qwen2.5 工具模板与训练数据分布的特定属性，而不是普适的新机制。

## 6. F4：普通平衡 SFT

F4 使用同一 Base 初始化，训练数据为 160 个冻结配对的 320 条样本，Call/Reject 严格 1:1；开发集为 4 对 8 条。配置为 rank-8 LoRA、学习率 `1e-4`、有效 Batch 8、4 个 epoch，不使用新损失、RL、判断头或 Oracle 输入。

当前共享服务器两张 GPU 均被其他用户持续占用。完整自动流水线已设置资源门控：GPU 1 空闲显存不少于 18GB、利用率连续三分钟不高于 40% 才启动；训练成功后自动执行原生 ID/OOD 评测和训练后 Probe。该设置是为了不干扰他人实验；训练结果完成后将补入本节，不能把尚未运行的配置当作实测结论。

## 7. 竞争解释与当前机制判断

| 竞争解释 | 证据判断 |
|---|---|
| Parser 把合法拒绝判错 | 不支持；F1 无一次拒绝且解析失败为 0 |
| Prompt 没有允许拒绝 | 不支持；B/C/D 均无行为改变 |
| 原生上下文完全不含合同信息 | 不支持；后层 Probe 在 OOD-Family 上 AUROC 0.890 |
| 表征等于可直接使用的内部判断模块 | 不支持；绝对校准和自主生成判断明显较弱 |
| 正确判断文本可直接驱动行动 | 强烈不支持；Oracle 下仍 100% False Call |
| 工具模板产生强调用先验 | 当前证据支持；注册工具时自主判断被直接替换为工具调用 |
| 所有错误都是 Knowing–Doing Gap | 证据不足；可满足侧完整调用仅约 47%，参数生成仍是独立瓶颈 |

## 8. 与现有工作的关系

- [When2Tool / Probe&Prefill](https://arxiv.org/abs/2605.09252) 已报告生成前隐藏状态可线性读出工具必要性，并通过 Probe&Prefill 改变后续行为。本项目的“后层 Probe + 前置判断”不具备方法新颖性；差异仅可能来自动态合同可满足性、配对执行语义和未见工具家族。
- [Model-Adaptive Tool Necessity](https://arxiv.org/abs/2605.14038) 已把内部认知与最终调用动作区分，并报告晚层方向失配。F2/F3 与其 Knowing–Doing 现象高度相关，不能只换成“合同”术语就宣称独立发现。
- [DeIllusionLLM](https://arxiv.org/abs/2603.22619) 面向含缺陷科学问题，使用任务级自回归判断和自蒸馏；它与本项目的工具合同场景不同，但已经覆盖“先识别不可满足输入，再改变生成”的核心范式。
- [Learning to Self-Verify](https://arxiv.org/abs/2602.07594) 研究验证能力与生成能力的不对称，并以多任务强化学习连接两者。当前没有证据支持在本项目中直接引入类似复杂目标。

## 9. 当前研究决策：REVISE

F0–F3 证明了一个真实、可重复的现象：原生后层表征中存在合同差异信号，但短提示、显式判断文本、冻结 Probe 乃至 Oracle 都没有改变 Base 的原生调用动作。然而，这还不足以支持 CCPD-v2：

1. 与 When2Tool 和 Model-Adaptive Tool Necessity 的机制高度重合；
2. 当前接入方法只是文本注入，失败可能来自工具模板的强格式先验；
3. 尚未回答普通平衡 SFT 是否已经足够；
4. OOD-Constraint 只有 4 对，不能承担强泛化结论；
5. 可满足侧仍有约一半参数不完全正确，决策与参数绑定不能混为一谈。

最终 GO/REVISE/NO-GO 取决于 F4：若普通 SFT 同时改善 ID 与 OOD，则不需要新学习目标；若只改善 ID，而 OOD 表征仍可稳定读出且简单推理接入无效，才形成进一步推导最小学习原则的空间。无论哪种结果，都不恢复 CCPD-v1 的稀疏配对奖励。
